# Gap and research-question source readings

These are implementation notes, not instructions to install or use the listed projects. The executable checks and decision workflow are in this skill's own `scripts/check_gap_record.py`, `scripts/check_question_card.py`, `scripts/check_ai_cs_research_plan.py`, `gap-audit.md`, `ai-cs-gap-rq-experiment.md`, and `research-workflow.md`. Local source snapshots were inspected on 2026-11-21; upstream code can change. No source code was copied into the validators.

| Source inspected | Mechanism read | Capability implemented here | Boundary retained |
|---|---|---|---|
| [Sakana AI Scientist](https://github.com/SakanaAI/AI-Scientist), `ai_scientist/generate_ideas.py` | Idea generation/reflection, Semantic Scholar/OpenAlex search, and a bounded novelty loop. Its S2 path defaults to ten hits per query and passes abstracts into the novelty prompt; a Boolean `novel` field is saved after the loop. | An iterative lead → source → challenger workflow with query logs, failure states, named closest works and a non-Boolean disposition. | A top-ten abstract pass, model self-critique, and failed API request cannot establish novelty. No Sakana implementation code is redistributed. |
| [Stanford AI-Researcher](https://github.com/NoviScl/AI-Researcher), `ai_researcher/src/experiment_plan_gen.py` and `novelty_check.py` | Expands an idea into an executable experiment plan with datasets, baselines, metrics, examples and fallback; novelty code proposes 1–3 Semantic Scholar keyword queries and scores nearby abstracts, then makes a binary match judgment. | AI/CS plan generation now requires a cheap engineering diagnostic, rival-discriminating primary test, follow-up control, and cross-links from the gap and RQ; the panel score is tied to full-text closest-work evidence. | A detailed generated plan may still be infeasible or motivated by a false gap. Abstract similarity and binary high-level match cannot settle method equivalence or quantify novelty. |
| [Lit-Gap](https://github.com/saulmcphd/lit-gap), `app/pipeline.py` and `app/analysis.py` | Multi-source search, deduplication/ranking, mined author future-research statements, candidate-specific verification searches, structured gap output. | Evidence roles explicitly distinguish author future work from observed results; candidate-specific kill queries are cross-linked to a gap record. | A single targeted query may miss a closing precedent; author statements and an abstract-heavy corpus generate leads only. The checker rejects author future work as the sole basis of a positive candidate. |
| [ResearchRadar](https://github.com/diptiman-mohanta/ResearchRadar), `.claude/skills/research-gap-miner/SKILL.md`, `novelty-auditor/SKILL.md`, and `research-idea-lab/SKILL.md` | Review-evidence grouping, independent-work counting, later-work checks, closest-paper comparison, explicit novelty failure/abstention, hypothesis and falsification planning. | Source/study IDs, closest-work/locator cross-links, adversarial query status, positive-gap gates, and RQ decision branches. | Reviewer comments are selected evidence, not field consensus. A named nearby paper alone cannot kill a distinct idea, and repeated comments do not create independent studies. |
| [Good Question](https://github.com/Rimagination/good-question), `SKILL.md` | Information-sufficiency gate, source-backed/inference/unknown separation, distinct question lenses, convergence by importance/feasibility/falsifiability, Good Question Cards. | Generate distinct candidates from source-backed uncertainties, discard non-consequential or unanswerable ones, then give each survivor a prediction/rival/pilot card. | The source is a question-development method, not a comprehensive retrieval backend or a validated gap judge. |
| [K-Dense Scientific Agent Skills](https://github.com/K-Dense-AI/scientific-agent-skills), `skills/hypothesis-generation/SKILL.md`, `skills/scientific-critical-thinking/SKILL.md`, `skills/scientific-brainstorming/SKILL.md` | Separate target question and hypothesis, dated evidence boundary, rival explanations, estimand and measurement, discriminating predictions, evidence-risk appraisal and explicit human accountability. | The RQ workflow asks for units, construct/estimand, rival predictions, disconfirming and indeterminate outcomes, technical/measurement artifacts, and prospective-vs-exploratory timing. | A filled card or structurally valid JSON does not validate causal identification, measurement or source truth. Domain review remains necessary. |

## Adversarial cases behind the gap-record checker

The fixture and local tests specifically challenge: an abstract-only supporting record; unread closest work; a direct precedent mislabeled as an open gap; a failed/rate-limited kill search; an author future-work sentence used as sole support; an unresolved local engineering failure; unscreened retrieved hits; a wrong source-to-locator link; and one-index coverage without an explicit exception. They test the validator's behavior, not its scientific recall or correctness in a real field.
