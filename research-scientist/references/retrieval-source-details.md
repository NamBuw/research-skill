# Retrieval and reading source study

Code-reading notes for the skill's built-in document-grounded workflow. These are provenance, not runtime dependencies. Snapshots are those checked in `/tmp/research-repos` on 2026-11-21; local hashes are recorded in [repository landscape](repository-landscape.md). The implementation here is original standard-library code and workflow text, not imported upstream code.

| Source and inspected path | Operational detail learned | Included capability and boundary |
|---|---|---|
| [GPT Researcher](https://github.com/assafelovic/gpt-researcher), `gpt_researcher/skills/researcher.py`, `ResearchConductor.conduct_research` | Routes supplied URLs, web, local and hybrid source modes; tracks visited URLs and source context. | Explicit local/live/hybrid mode selection, source manifest and identity checks. We do not bundle its web retrievers or LLM orchestrator. |
| [Stanford STORM](https://github.com/stanford-oval/storm), `knowledge_storm/storm_wiki/modules/knowledge_curation.py`, `StormKnowledgeCurationModule._run_conversation`; `knowledge_storm/storm_wiki/modules/outline_generation.py`, `StormOutlineGenerationModule.generate_outline` | Runs perspective-specific retrieval conversations, gathers an information table, then revises an outline from collected material. | Perspective-specific subquestions, an editable information table and claim-linked outline. Personas are not independent evidence, and an outline is not a truth check. |
| [PaperQA2](https://github.com/Future-House/paper-qa), `src/paperqa/agents/tools.py`, `PaperSearch` and `GatherEvidence`; `src/paperqa/docs.py`, `aquery` | Distinguishes adding papers, gathering question-specific evidence and answering; empty context triggers abstention. | Separate paper discovery, passage gathering and answer gates. The local helper retrieves lexical passage leads and reports source counts, but does not reproduce its embedding/index/LLM stack. |
| [Perplexica successor Vane](https://github.com/ItzCrazyKns/Vane), `src/lib/agents/search/researcher/actions/search/academicSearch.ts` | Its academic action is enabled by classification and source choice, caps one call at three queries, and sends them to arXiv, Google Scholar and PubMed engines. | Route scholarly and user-owned sources explicitly; treat three queries and engine results as a bounded pass, not completeness. Its runtime search stack is not embedded. |
| [MinerU](https://github.com/opendatalab/MinerU), `mineru/render/_internal/content_list/v2.py` and `common.py` | Content List V2 is a list of pages containing typed items. Text spans, tables/equations, normalized bounding boxes and anchors can be present; blocks can be omitted. | `scripts/local_evidence.py` reads exported V2 page/item structure, retains page/bbox locators and flags layout-sensitive blocks. It is **not a PDF parser**; tables and OCR require original-page inspection. |
| [Khoj](https://github.com/khoj-ai/khoj), `src/khoj/processor/tools/online_search.py`, `search_online` | Generates subqueries, tries available engines in sequence and stops after first nonempty response. | Generate distinct subquestions but record actual engines and require complementary scholarly sources for novelty. Khoj's AGPL implementation is not copied or embedded. |

The bundled local retrieval's BM25-style formula is a general information-retrieval method, not a claimed novel method. It uses Unicode word tokens, per-segment term counts and document frequency. Its ranking is lexical, with no stemming, synonym handling, semantic recall estimate or scientific truth inference. The wrapper's useful property is inspectable source locator output; reliability still depends on source extraction and manual reading.
