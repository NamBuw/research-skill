# Source notes: research-agent repositories

## Scope and how to read this inventory

This inventory records a code/documentation reading of the eight repositories the user supplied, then selected related repositories focused on search, paper-grounded synthesis, research-gap discovery, question formation, hypothesis/idea generation, review screening, and autonomous research. The supplied projects were checked against their README/docs and relevant architecture or core pipeline files; large repositories' every vendored asset, dataset, historical commit, dependency, and test was not read line by line. Additional prototypes received a narrower README/core-file scan. The local snapshots were shallow Git checkouts read on **2026-11-21**; hashes below identify what was inspected, not a permanent quality ranking. Check upstream before relying on current features.

**Evidence levels used here:**

- **Paper or benchmark-backed, scoped:** a paper and/or benchmark exists, but its task, domains, measures, judges, and dates bound the evidence.
- **Useful workflow/tool with stated limits:** useful architecture or procedural method; does not establish general scientific validity.
- **Prototype / self-reported:** README/code claims or local tests exist, but no independent evaluation of gap/RQ correctness was found in the inspected material.

This is an implementation-oriented map, not a systematic review of every research agent on GitHub. Repository claims in tables below are attributed to their authors. This skill independently synthesizes practices; it does not copy repository source code or imply endorsement.

### Patterns adopted from the supplied set

1. Split question understanding, retrieval, evidence collection, synthesis, and writing into inspectable stages (GPT Researcher, STORM, PaperQA2).
2. Preserve question-to-source and claim-to-locator links; abstain when the local corpus or source coverage is too weak (PaperQA2, MinerU).
3. Keep human steering and editable research state (Co-STORM, Khoj).
4. Treat parsing, retrieval, agent critique, and code execution as fallible stages with separate validation (MinerU, PaperQA2, AI Scientist).
5. Route to smaller domain/task skills and use a review protocol instead of overloading the entrypoint (K-Dense).

## Dedicated gap-finder prototypes: useful mechanisms, weak validation

These are worth knowing because they implement the literal requested feature. The central failure mode is converting a retrieved corpus's sparsity, clusters, abstract text, or an author's “future work” sentence into a claim that the field has an important unsolved problem.

| Project | Inspected approach | Important limitation / proper use |
|---|---|---|

Strong candidate architecture, but output remains a lead to verify. |
| [ScholarScout](https://github.com/neej4/ScholarScout) · `6898b0b` | Multi-source routing, paper clustering/trend analysis, generated ideas with a source evidence pack/P-number grounding, similarity-based novelty check, and deep-dive plans. | “250M+ papers”/database breadth are repository claims. Citation-ID grounding and semantic similarity check whether a cited result is present or close, not whether the claim is entailed or the idea is novel. ## Benchmarks and evaluation resources for gap/RQ systems

| Resource | Why it matters | Boundary |
|---|---|---|
| [RINoBench](https://github.com/TimSchopf/RINoBench), [paper](https://arxiv.org/abs/2603.10303) | Expert-labeled research-idea novelty judgment (the checked paper describes 1,381 idea judgments and multiple automatic metrics). Makes human-agreement/novelty evaluation measurable and exposes the danger of trusting a plausible model explanation. | Novelty labels remain tied to the dataset's ideas, experts, and operational definition. A benchmark score does not establish the novelty of a new question in any field. |
| [HypoBench](https://github.com/ChicagoHAI/HypoBench), [paper](https://arxiv.org/abs/2504.11524) | Hypothesis-generation benchmark with 7 real-world and 5 synthetic tasks, 194 datasets across 12 domains; tests explanatory hypothesis generation against data/tasks. | Hypothesis quality/explanatory validity is not the same task as literature-wide research-gap discovery or RQ importance. Benchmark tasks and evaluation protocols remain bounded. The GitHub repo inspected is mainly the benchmark website/materials. |
| [AgentIdeaBench](https://github.com/moyunxiang/AgentIdeaBench), [paper](https://arxiv.org/abs/2609.07611) | Compares static ideas from supplied references with active ideation where the agent chooses search queries and papers; records tool/search traces across 40 subfields and 35 models. | Scored by LLM critics and uses a bounded Semantic Scholar search budget/frozen date. It is useful for evaluating search behavior and tool use, but not human certification of a specific gap. |
| [IdeaBench](https://github.com/amir-hassan25/IdeaBench), [paper](https://arxiv.org/abs/2411.02429) | Reference-grounded idea-generation benchmark built from 2,374 target papers across eight domains and 29,408 referenced works; compares generated ideas with target-paper contexts. | Similarity to a later/target paper and LLM-assisted “insight” ratings are proxies, not a general test of real-world originality, value, or feasibility. |
| [AI Idea Bench 2025](https://github.com/yansheng-qiu/AI_Idea_Bench_2025), [paper](https://arxiv.org/abs/2504.14191) | AI-domain benchmark with 3,495 target papers and corresponding motivating papers; evaluates ideas against ground-truth paper/reference contexts. | AI/ML and reference/target-paper benchmark framing; a model's overlap or judge score cannot establish novelty outside this corpus or measure whether a project succeeds when executed. |
| [CKM Benchmark](https://github.com/TaoJinkai/ckm-hypogen/tree/main/benchmark), [paper](https://arxiv.org/abs/2604.12243) | Frozen topics/literature phases and later papers provide temporal evidence for whether a hypothesis anticipates future work, a stronger test than self-judging in one prompt. | Later publication is a proxy for future alignment, not the full value, truth, importance, or causal validity of a hypothesis. |
| [IDEAgent Yield evaluation](https://github.com/declare-lab/IDEAgent) | Tests both idea quality and diversity rather than rewarding many near-duplicates; has fixed-topic baselines and lineage. | Quality judges, thresholds, topic set, and CS scope define the result. Diversity alone can reward a diverse collection of bad ideas unless quality is independently judged. |
| [IdeaScientist evaluation artifacts](https://arxiv.org/abs/2610.04074) | Separates gap finding, innovation, review, and proposal writing, enabling role/ablation and retrospective comparisons. | The linked portable skill is not the full trained/corpus system; paper results are scoped and model-judged. |
| [FirstResearch](https://github.com/louiswang524/FirstResearch) | Makes assumptions, mechanisms, falsifiers, and answerability inspectable in the question itself; includes configs and report artifacts for controlled comparisons. | Small topic set and blind LLM judge in the inspected paper; outputs need field experts and source checks. |
| [ScienceAgentBench](https://github.com/OSU-NLP-Group/ScienceAgentBench) and [DiscoveryBench](https://github.com/allenai/discoverybench) | Test downstream scientific data analysis, executable code, and data-driven discovery against tasks/verifiers, complementing prose-only ideation metrics. | They evaluate bounded computational tasks and code/data workflows, not whether a research gap matters or whether a literature review is complete. Code execution should use the provided isolation/evaluation harness. |

Other relevant research/review resources include [AgentSLR](https://github.com/OxRML/AgentSLR), [ASReview](https://github.com/asreview/asreview), [OpenScholar](https://github.com/AkariAsai/OpenScholar), and [PaperQA2](https://github.com/Future-House/paper-qa). They help with screening, retrieval, or synthesis; none by itself certifies a field-wide research gap.

The bundled discovery script later added arXiv Atom and PubMed E-utilities routes after checking the [arXiv API manual](https://info.arxiv.org/help/api/user-manual.html) and [NCBI E-utilities documentation](https://www.ncbi.nlm.nih.gov/books/NBK25499/). It uses arXiv `search_query`, `start`, and `max_results`, and PubMed `esearch` followed by `esummary` for returned PMIDs. Query translation, provider ranking, API totals, and indexing remain provider-specific. A few successful pages do not measure recall.

### PaperQA2 citation-path reading

In snapshot `c692d0d`, `src/paperqa/docs.py` (`aquery`, document ingestion) and `src/paperqa/prompts.py` were inspected. When context serializes to an empty answer context, `aquery` emits a cannot-answer response. With context, its answer prompt restricts citation keys to the provided context. At ingestion, if a citation is not supplied, the code can ask a model to format a citation from extracted text, fall back to an `Unknown` filename/year string, and optionally ask a model to extract DOI/title/authors from that generated citation. These are useful operational behaviors, but neither a syntactically valid key nor model-extracted DOI proves bibliographic identity or claim entailment. The full test suite and live citation error rate were not evaluated. For decisive claims, resolve identity through publisher/DOI metadata and read the original passage. Keep `citation key exists`, `identity verified`, and `claim supported by passage` separate.

The K-Dense helper was read through its verification path, not executed or benchmarked here. The research skill should not convert a successful DOI lookup into a scientific-evidence pass.
